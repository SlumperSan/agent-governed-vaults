# Web audit, 2026-10-20

Scope: the frontend apps `apps/web`, `apps/vaults-ui`, `apps/site`, `apps/app`. There is no single "web app" package: `apps/web` is a dependency-free read-only prototype with pure logic modules, `apps/vaults-ui` is the only app that signs, `apps/site` and `apps/app` are static and do not sign.

Method: `npm ci` (npm 11, matching CI), `npm audit`, typecheck, lint, existing tests, then a source review of wallet connect, signing, HTML sinks, client secrets and headers. Nothing in this audit changes public copy or contracts. Every suggested fix is code or config only; a new error string is the one copy-adjacent item and is noted.

The vaults-ui wallet client is built with `chain: TARGET_CHAIN` (`wallet.tsx:125`), and viem 2.55.19 `sendTransaction` re-reads `eth_chainId` and calls `assertCurrentChain` before every send (`node_modules/viem/_esm/actions/wallet/sendTransaction.js:92-99`), so the write path is covered. ## Checked, no issue found

- Chain id: `wallet.tsx` checks `eth_chainId` at connect (178-181), handles `chainChanged` (141-147, drops to `wrong-network`), and `switchToTarget` re-reads the chain.
- Allowance: no `maxUint256` anywhere in `apps/`. `approve()` is called with exactly `amountUsdc` to the vault (`chain-actions.ts:582`), simulated first, receipt awaited (587). Residual: an exact allowance remains if the deposit then fails.
- Input validation: amounts go through `parseUnits` (`format.mjs:200-212`, digits only, bounded decimals, nonzero). The vault address is checked with `isAddress`. No URL params feed `vaults-ui` signing. No slippage or minOut parameter exists in any UI-sent call.
- Simulate before sign, sanctions screen first, closed-vault writes refused, receipt status checked (`chain-actions.ts:544-556`, `tx-status.ts`).
- `apps/web/src/wallet-refusals.mjs` fails closed (`canSign` false for `refused` and `unknown`).
- `eval`, `new Function`, `document.write`, `insertAdjacentHTML`, `javascript:` URLs: none in any of the four apps.
- Client secrets: the only env vars read are public (`VITE_RPC_URL`, `VITE_CHAIN_ID`, `VITE_VAULT_ADDRESSES`, `VITE_VAULT_NAME`, `VITE_FACTORY_ADDRESS`, `VITE_V3_FACTORY`, `VITE_TARGET_CHAIN`). The one committed env file, `apps/vaults-ui/.env.example`, holds a public RPC URL with no key.
- CSP: `site`, `vaults-ui` and `app` all set a strict CSP on `/*` (`default-src 'none'`, `script-src 'self'`, no `unsafe-inline` or `unsafe-eval`, `frame-ancestors 'none'`); `vaults-ui` `connect-src` is `'self'` plus one RPC origin.
