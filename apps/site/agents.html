The machine-readable path

Every page here is for a person. This one is not.

An agent does not need the rest of this site. It needs one free call that describes the interface, a way to pay for reads, and the contract addresses. That is the whole integration surface. It is documented rather than negotiated.

This describes source code and a published interface. Nothing is deployed to mainnet, and the current testnet deployment carries no value.

Bootstrap

One free call, then everything else follows from it.

Discovery is unmetered on purpose. An agent should be able to learn what a service costs before it has spent anything, and it should learn it from the service rather than from a blog post that has since drifted.

Free
GET /.well-known/x402 returns pricing, the route list, and pointers to the specs. GET /health and GET /metrics are free as well. Every other route is metered.
Metered
Reads over the projected index state: the vault list, a single vault, the operator leaderboard. Each returns 402 with a PAYMENT-REQUIRED header naming the scheme, asset, amount, recipient and nonce.
Payment
Build an EIP-3009 TransferWithAuthorization for that quote, sign it EIP-712 with the agent's own wallet, and retry with a PAYMENT-SIGNATURE header. The response carries a PAYMENT-RESPONSE receipt. A facilitator verifies and settles on-chain; the API server holds no keys.
Acting
The metered API is read-only. Deposit, activate, propose, commit, reveal, exit: every state change goes straight to the contracts. The API is a convenience for reading, never a path to authority.

There is no key to request and no allowlist to join, and nothing on this site to sign up for. An agent that can sign an EIP-712 message and send a transaction has everything it needs.

What an agent can and cannot do

Membership is bought, not granted.

Deposit
Permissionless. The contracts gate on amount alone (a minimum deposit and a capacity cap) and screen nobody. Any address meeting those can join. Vault #1 will screen at the front end, which is a different thing and binds nothing on-chain.
Propose
Follows stake, not identity. A member holding at least the vault's proposal threshold may open a proposal; an operator holding no shares may not. There is no operator check in the governance contract at all.
Vote
Commit then reveal. The contract takes an arbitrary salt and stores nothing for you, so an agent that loses its memory between the two phases cannot reveal and its vote is lost. The reference agent solves that by deriving the salt from a signature it can reproduce rather than storing it. That is a client technique, not a protocol property, and an integrator writing their own client gets it only by implementing it.
Exit
Pro-rata and in kind, and subject to two conditions worth reading before you build around it. From the moment the reveal phase opens on any live proposal (not from the moment one passes) until that proposal executes, is defeated, or its execution window lapses, the request is queued and settles at post-execution NAV; a proposal that is ultimately defeated still forced your exit into the queue while it was live. That is a delay. An oracle freeze is not. Every function that reads NAV reverts while a price feed is stale, exits included, and there is no escape hatch — you cannot leave at any price until the feed recovers. If the feed is retired rather than late, that is permanent. See the risks page.
The gate that will surprise an integrator first

A first deposit sits in a four-hour observation window before it becomes shares. During that window it has no vote and no share price, and it is fully reclaimable. An agent that deposits and immediately checks its balance will read zero. That is correct, not a failure.

skipWindow() opts out and activates a pending deposit immediately. It is irrevocable, and the cost is not obvious: pending capital is the only capital that stays reclaimable while the oracle is frozen. Opting out forfeits that permanently.

Reference client

There is a working agent in the repository.

It reads the metered API and the chain, decides whether to join, vote or exit, and prints the exact calls it would make. It is dry-run by default and cannot sign without an explicit environment gate.

Read it as a worked example of the integration, not as a strategy and not as product code. It sits outside the scope of the contract security review, and running it live is what exposed two launch-class bugs in it. One gate could never admit a new operator. A deposit path set no token allowance and therefore reverted in every configuration as shipped. Both are fixed with regression tests. Both were invisible to mocks.

Before you point anything at this

Read the risks page too.

An autonomous integrator is exactly the reader most likely to skip it, and the failure modes are not ones a retry loop recovers from. A stale price feed freezes every function that reads NAV, exits included. A bug cannot be patched, because the contracts cannot be changed. Nobody makes anyone whole, and there is no guarantee of any outcome.

Standing facts

No token. No points. No airdrop. No presale.

Source-available under BUSL-1.1 — not open source.

Nothing on this site is an offer, a solicitation, or financial advice. Not deployed to mainnet. No mainnet deployment of the current code exists, and a Base Sepolia deployment is a testnet trial with no real value at stake. Interests in these vaults may be treated as securities or as collective investment scheme interests in some jurisdictions. Access from restricted jurisdictions is intended to be geofenced at the front end; that is a good-faith measure and not a guarantee, because the contracts are permissionless and can be called directly by anyone.
