The machine-readable path

Every page here is for a person. This one is not.

An agent does not need the rest of this site. It needs the chain id, the contract addresses, and an ABI. That is the whole integration surface. There is no key to request, no allowlist to join, and no gateway between an agent and a vault.

Bootstrap

Three reads and you are integrated.

The chain
Robinhood Chain mainnet, chain id 4663. The settlement token is USDG.
The addresses
The factory, the governance contract, the fee engine, the operator registry and the oracle are listed on the status page and committed to contracts/config/deployments/robinhood-mainnet.json, each read back on-chain.
The ABIs
Build the contracts and read them out of contracts/out/: VaultCore, Governance, FeeEngine, OperatorRegistry, ChainlinkOracle, AggregationRouterAdapter, SubVaultRegistry, VaultFactory.
The wiring you must check yourself
Read VaultFactory.allowSubVaults() on the factory you integrate against; it is a per-deployment immutable, not a protocol property. Read OperatorRegistry.operatorOf(vault) rather than a display name: vault creation is permissionless, so verify the operator, not the label.

What an agent can and cannot do

Membership is bought, not granted.

Deposit
Permissionless. The contracts gate on amount alone — a minimum deposit and a capacity cap — and screen nobody. Any address meeting those can join.
Propose
Follows stake, not identity. A member holding at least the vault's proposal threshold may open a proposal; an operator holding no shares may not. There is no operator check in the governance contract at all.
Vote
Commit, then reveal. The contract takes an arbitrary salt and stores nothing for you, so an agent that loses its memory between the two phases cannot reveal and its vote is lost. The reference client derives the salt from a signature it can reproduce rather than storing it. That is a client technique, not a protocol property; an integrator writing their own client gets it only by implementing it.
Exit
Pro-rata and in kind. From the moment the reveal phase opens on any live proposal — not from the moment one passes — the request is queued and settles at post-execution NAV. Governance.hasPendingExecution(vault) is the exact predicate. What that costs you, and what an oracle freeze does to it, is in the Disclaimers.
The gate that will surprise an integrator first

A first deposit sits in a four-hour observation window before it becomes shares. During that window it has no vote and no share price, and it is fully reclaimable. An agent that deposits and immediately reads its balance will read zero. That is correct, not a failure.

skipWindow() opts out and activates a pending deposit immediately. It is irrevocable, and what it forfeits is set out in the Disclaimers.

Reference client

There is a working agent in the repository.

It reads the chain, decides whether to join, vote or exit, and prints the exact calls it would make. It is dry-run by default and cannot sign without an explicit environment gate.

Read it as a worked example of the integration, not as a strategy and not as production code. Its review scope, and the two launch-class bugs running it live exposed, are in the Disclaimers.
